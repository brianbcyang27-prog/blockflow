## 一、30 秒電梯簡介（背起來）

> BlockFlow 是一個 **AI 每日規劃助手**，幫助學生用「三區塊系統」解決「今天要怎麼安排」的決策疲勞。
>
> 一天分成 **Focus（專注）· Personal（個人）· Recovery（恢復）** 三個區塊，搭配 AI 助理 **Nova**，會記得你的事情、聽得懂你說話、幫你把行事曆排好。
>
> 它是純前端的 PWA，手機電腦都能裝、離線也能用，AI 由 NVIDIA 的模型驅動。

## 三、AI 架構（Nova 怎麼運作的）

```
使用者講話/打字
      │
      ▼
瀏覽器（純 JS 前端）
      │  api-proxy.py（本地代理）→ 或 Firebase Hosting rewrite /api/chat → Cloud Functions
      ▼
NVIDIA API（integrate.api.nvidia.com/v1/chat/completions）
      │
      ▼
可切換模型：
  • Llama 3.1 8B Instruct（預設）
  • Llama 3.3 Nemotron Super 49B（更強）
  • Gemma 4 31B / Gemma 2 2B
  • Llama 3.2 11B Vision（OCR：掃描講義/文件）
```

**Nova 的四大能力（都有實作）：**
1. **🧠 記憶系統** — 記住使用者偏好，跟 ChatGPT 一樣會「記得你」
2. **🎤 語音 I/O** — 瀏覽器語音辨識（STT）+ 多種 TTS（Kokoro / ElevenLabs / 瀏覽器內建），搭配自訂波形動畫
3. **📎 附件分析** — 上傳檔案（含圖片 OCR），AI 幫忙整理重點
4. **📅 行事曆操作** — 直接對話排行程、AI 自動分類事件

> 💡 **講稿金句**：「Nova 不是一個聊天機器人，它是住在你行事曆裡面的助理。」

## 四、技術架構（老師最愛問這張）

| 層 | 技術 | 說明 |
|----|------|------|
| 前端 | 純 JavaScript + HTML + CSS | 無框架、零依賴，RWD 最小支援 iPhone 7 |
| 後端 | Firebase | Auth（Google 登入）+ Firestore（雲端備份）+ Hosting |
| 雲端函式 | Cloud Functions（`functions/`） | 生產環境的 `/api/chat` 代理 |
| 本地代理 | `api-proxy.py` | 開發時把請求轉到 NVIDIA 並加上 CORS |
| AI | NVIDIA API | 多模型可切換（見上節） |
| 資料 | localStorage（本機優先）→ Firestore（登入後同步） | `migration.js` 負責把本機資料搬上雲端 |
| 部署 | Firebase Hosting | 線上版：`https://blockflow-28d39.web.app` |

**資料流：** 未登入＝全部存本機（localStorage）；Google 登入後＝一鍵遷移到 Firestore，跨裝置同步。

## 六、Live Demo 腳本（5–7 分鐘，照順序做）

- 講：「看到沒，一句話就排好了 — 這就是 AI 排程。」

## 七、Q&A 密技表（被問到直接抄答案）

### Q：為什麼用 NVIDIA 不用 OpenAI / Gemini？
- 學生有**免費額度**（40 RPM），不用自己付錢
- 單一整合端點，一個 key 就能用多個模型（Llama、Gemma、Nemotron…）
- 不用自己架 GPU，對學生專案是成本最低的選擇

### Q：資料存在哪裡？安全嗎？
- 未登入：全部存在**本機 localStorage**，不會上傳
- 登入 Google 後：一鍵遷移到 **Firestore**（`migration.js`），有 security rules 控管
- Firestore 規則在 `firestore.rules`，只有自己的資料可以讀寫

### Q：AI 是不是只是接 API 而已？
- 不只是。我實作了：**記憶系統**（記得用戶偏好）、**語音輸入輸出**、**附件/OCR 分析**、**自然語言轉行事曆**、**AI 事件分類**、**每日簡報**、**每週報告**
- 這些是把「模型能力」變成「產品功能」的工程，不是呼叫 API 而已

### Q：前端為什麼不用 React / Vue？
- 刻意選**零框架純 JS**：PWA 載入更快、無依賴、好維護，對這種工具型產品剛好
- 程式碼有模組化（`storage.js`、`timer.js`、`calendar.js`…），不是義大利麵

### Q：你遇到最難的問題是什麼？
- 建議答：**語音系統** — 瀏覽器語音在不同平台行為不一致，要做 fallback 到第三方 TTS（Kokoro、ElevenLabs），還自己畫了語音波形動畫
- 或：**Firebase 與本機資料同步** — 要先確保 localStorage 優先、登入後無縫遷移

### Q：未來要做什麼？
- 跨裝置同步最佳化、更強的 AI 排程演算法、跟學校課表整合、市場化（見第三部分講稿：定價策略）

## 八、不能講的（誠實清單，避免被戳破）

- ❌ 不要說「AI 很聰明」— 要說「AI 會記得你、會排程」，講具體功能

- ❌ 不要誇大用戶量 / 付費用戶 — 目前是個人專案，商業模式是「規劃中」
