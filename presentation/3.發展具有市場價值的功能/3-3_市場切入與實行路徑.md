# 市場切入策略與執行路徑

**目標**：從現在的「無收入 PWA」到「月收 $5K+ 的產品」

---

## 市場定位

### 我們的用戶畫像

```
Primary: 大學生 / 研究生（18-25 歲）
  └ 痛點：課表亂、作業截止日記不清、讀書沒方向
  └ 行為：用手機居多、願意嘗試新工具、價格敏感
  └ 機會：養成習慣後至少用 2-4 年

Secondary: 年輕工作者（25-35 歲）
  └ 痛點：工作生活失衡、待辦事項太多、專注力不足
  └ 行為：用電腦為主、對生產力工具有付費習慣
  └ 機會：願意付 $5-10/月 來提升效率
```

### 一句話定位（Pitch）

> **BlockFlow 是學生的 AI 每日規劃助手，用三區塊 + AI 幫你解決「今天要怎麼安排」的決策疲勞。**

## 三階段執行路徑

### Phase 1：驗證期（現在 — 1 個月）

**目標**：驗證用戶是否願意付費

```
行動清單：
1. 在 settings.html 加入「贊助開發」按鈕（Buy Me a Coffee / Stripe）
   → 測試有沒有自然付費意願

2. 加入「Pro 即將推出」的提示（不擋功能）
   → 蒐集用戶 email 願望清單

3. 在 GitHub 開啟 Sponsor
   → 測試開源社群支持度

4. 在台灣大學 / Dcard / Reddit 發佈
   → 測試市場反應

5. 加入基本 telemetry（使用統計，不上傳個人資料）
   → 了解哪些功能最常用、哪些是 Pro 最佳候選
```

**成功指標**：
- ✅ 50+ 個 Pro 等候 list email
- ✅ 自然贊助收入 > $0
- ✅ 日活躍用戶（DAU）> 100

---

### Phase 2：MVP 收費期（1-3 個月）

**目標**：正式推出 Pro 方案，達到 MRR $1,000+

```
行動清單：
1. 完成金流串接（Stripe / Paddle / 藍新）
2. 實現 Feature Flag 系統（Free vs Pro 功能切換）
3. 實現 Pro Key 管理（後端驗證）
4. 建立 NVIDIA 內建 Key 的 Proxy（用量控制）
5. 實現 ElevenLabs 配額管理
6. 推出 Pro 方案（$4.99/月）
7. 在 Product Hunt 發布
8. 在 Hacker News / Reddit / 台灣社群宣傳
```

**技術需求**：
```
┌─────────────────────────────────────┐
│           Firebase Backend           │
│  Functions 處理：                    │
│  ├── Pro Key 驗證 + 發放            │
│  ├── NVIDIA Proxy（限 Pro 用戶）    │
│  ├── ElevenLabs 配額計數器           │
│  └── 訂閱管理 Webhook               │
├─────────────────────────────────────┤
│          前端 Feature Flag           │
│  const isPro = checkProStatus()     │
│  if (!isPro) { showUpgradeModal() } │
└─────────────────────────────────────┘
```

**成功指標**：
- ✅ MRR > $1,000（約 200 個 Pro 用戶）
- ✅ Free → Pro 轉換率 > 3%
- ✅ 月流失率 < 8%

---

### Phase 3：成長期（3-6 個月）

**目標**：規模化，MRR $5,000+

```
行動清單：
1. 推出學生方案（.edu 驗證）
2. 推出年繳方案（$49/年）
3. 推出 App Store 版本（WebView wrapper 或 PWA 推廣）
4. 加入推薦計畫（Referral Program）
5. 與學校 / 補習班合作（B2B 通路）
6. 推出 AI 洞察儀表板（Pro 限定）
7. 優化留存（推播通知、重複事件、週檢視）
8. 日文 / 韓文 / 英文版發布
```

**B2B 通路機會**：
```
補習班/學校購買 BlockFlow 給學生使用
  ├── 每個學生 $2/月（大量折扣）
  ├── 老師可查看班級平均專注時間（去識別化）
  └── 適合：國高中生讀書規劃、補習班課表管理
```

**成功指標**：
- ✅ MRR > $5,000
- ✅ MAU > 50,000
- ✅ 年留存率 > 60%

## 風險與對策

| 風險 | 影響 | 對策 |
|------|------|------|
| **用戶不願意為 PWA 付費** | 高 | 驗證期先測自然贊助；若失敗→加速 Native App |
| **NVIDIA API 成本太高** | 中 | Pro 用量限制（每月 5000 次對話）；多模型 routing（便宜模型打簡單問題） |
| **Free 用戶太多，Pro 太少** | 中 | 調整 Free 限制（但不破壞核心體驗） |
| **被大廠抄襲（Apple / Google）** | 低 | 三區塊概念簡單，但 AI 記憶 + 語音生態系是護城河 |
| **Firebase 成本隨用戶成長** | 低 | Firestore 免費方案足夠撐到 50,000 MAU |
| **學生沒信用卡** | 中 | 電信代扣、LINE Pay、超商代碼、禮物卡 |
